## 재현 가능한 표집 목록

`manifests/frame_samples.csv`는 추출할 프레임의 **인덱스 목록**이다. 영상 파일이나 사람 정답을 생성한 것이 아니다.
명목상 프레임 시각은 `frame_id/FPS`이며 표집 간격은 실제 계산값에서 1초 이상이 되도록 프레임 간격을 올림했다.
lot_1처럼 FPS가 15.00000487로 보고되면 16프레임 간격을 사용한다. 파일의 실제 가변 타임스탬프 검증은 후속 확인 사항이다.

| 용도 | 프레임 후보 수 | 사용 목적 |
| --- | --- | --- |
| 보정 | 141 | 칸별 빈자리·점유 특징 분포와 임계값 후보 |
| 검증 | 58 | 필터·형태학·결합·시간 안정화 T 선택 |
| 테스트 | 54 | 설정 동결 후 최종 측정 |

테스트 200프레임 목표까지 **146프레임이 부족**하다. 기존 사건이 분할 양쪽에 걸리지 않도록 경계를 옮기면서 표본 수가 줄었다. 같은 프레임 복제나 1초 미만 표집으로 채우지 않는다.
추가 촬영·사용 가능한 연속 영상 또는 별도 세션을 확보해 독립적인 테스트 구간을 늘려야 한다.
공통 영상은 20칸 ROI와 3칸 파일럿 정답이 있다. 나머지 영상 ROI·정답은 없어 테스트의 빈자리·점유 균형·칸-프레임 수와 사건 10건 목표는 아직 확정하지 않았다.

## 최종 성능평가 동결 전 남은 조건

- 사용자는 세 영상을 MIT 공개 자료라고 확인했다. 그 근거로 프로젝트 개발·평가용 채택을 확정했으며, 저장소 표기와 사용자 확인은 `rights_review.json`에서 구분한다.
- `session_id`의 `clip_...`는 같은 파일을 묶는 관리 ID다. 촬영 세션의 독립성이 확인됐다는 뜻은 아니며 촬영일은 비워 두었다.
- 시간 순서 표집으로 기존 사건의 분할 걸침을 찾아 경계를 옮겼다. 다른 시점 ROI와 독립 팀원의 연속 사건 주석을 추가해 최종 평가 전에 다시 확인한다. 에이전트의 시간 표집 검토를 사람의 연속 영상 검수 완료로 세지 않는다.
- 이 단계에서 일부 테스트 구간의 장면은 분할 설계를 위해 확인했다. 테스트를 전혀 열람하지 않았다고 주장하지 않는다. 테스트 정답·검출 성능으로 알고리즘이나 분할을 선택하지 않는다.
- 각 블록 시작 시 시간 안정화 상태·타이머를 초기화한다. 다른 분할의 상태나 프레임을 이어받지 않는다. 사건 지연용 연속 영상도 해당 분할 안에서만 사용한다.
- 이번 목록은 10주차 개발 범위로 고정했다. 사건 경계·정답 규모·다른 시점 ROI를 보완할 때 새 정책 버전으로 이력을 남긴다. 테스트 결과에 맞춰 재분할하지 않는다.

## 검증

프로젝트 루트에서:

```powershell
.\.venv\Scripts\python.exe scripts/validate_splits.py
.\.venv\Scripts\python.exe -m pytest tests/test_splits.py -q
```

검증기는 원본 SHA256, 알려진 영상·그룹 ID, 실제 디코딩 범위, 구간 중복·간격, 중복 원본과 표집 프레임 중복을 검사한다.
결과는 `manifests/split_validation.json`, 분할 정책과 구간 목록 SHA256은 `manifests/split_policy.json`에 보존한다.
해시가 다른 목록으로 바뀌면 중단하며 변경 사유를 검토해 정책 버전을 갱신해야 한다.

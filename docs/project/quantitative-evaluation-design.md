# 주차면 점유 검출 정량 평가 프로그램 설계

학교 앞 주차장 저장 영상에서 픽셀 비율, 라플라시안, 연결성분 필터, 시간 안정화의 효과와 처리 비용을 같은 조건으로 비교한다. 검증 결과로 시연 구성을 선정하고, 확정한 설정으로 별도 최종 테스트를 실행한다. 검출기가 낸 최종 상태를 공통 평가 함수에 넘겨 구성별 지표를 같은 기준으로 계산한다.

## 비교할 알고리즘

| ID | 구성 | 비교에서 확인할 점 |
| --- | --- | --- |
| A | 픽셀 비율 | 픽셀 비율 기준 성능 |
| A-CC | 픽셀 비율 + 연결성분 필터 | A 대비 노면 잡음 제거 효과와 계산 비용 |
| B | 라플라시안 | A와 다른 특징으로 얻는 기준 성능 |
| C | 픽셀 비율 + 라플라시안 판정 결합 | A·B 각각과 비교한 두 특징의 결합 효과 |
| D | C + 시간 안정화 | C 대비 잘못된 상태 전환, 보류, 입·출차 지연의 변화 |
| D-CC | D의 픽셀 비율 경로에 연결성분 필터 추가 | 같은 안정화 시간의 D 대비 필터 효과 |

D와 D-CC는 각각 안정화 시간 0.5초와 1.0초를 평가한다. 결과에는 `D-0.5`, `D-CC-0.5`처럼 안정화 시간이 포함된 고유 구성 ID를 쓴다. A-CC와 D-CC는 같은 연결성분 최소 면적으로 실행한다. 최초 비교에서는 현재 시험값인 12픽셀을 쓸 수 있다. A나 B가 시연 후보에 남으면 해당 단독 방식에 안정화를 적용한 결과도 비교한다.

## 입력과 실행 명령

기존 영상 목록, ROI JSON, 분할 CSV, 프레임 정답 CSV를 사용한다. 실행 목록 JSON에는 입력 파일 경로와 비교할 구성의 설정만 모은다. 한 목록에 여러 촬영본을 넣을 수 있다.

| 입력 | 기존 형식과 추가로 필요한 항목 |
| --- | --- |
| 영상과 ROI | 영상별 `video_id`, 원본 파일, ROI JSON, 고정 시점을 식별할 `view_id`. 영상 해시·해상도·칸 ID를 확인한다. 같은 고정 시점의 세션에서만 같은 칸의 보정값을 공유한다. |
| 분할 CSV | 기존 `video_id,session_id,split,start_s,end_s`. 구간은 `[start_s,end_s)`로 처리한다. 같은 원본의 구간은 최소 10초를 띄우며, 같은 입·출차 사건은 한 구간에 둔다. |
| 프레임 정답 CSV | 기존 `video_id,frame_id,timestamp_s,slot_id,label`. 보정용·검증용·최종 테스트용 파일을 나누고, 각 정답의 키와 분할 소속을 확인한다. `frame_id`는 0부터 시작한다. |
| 입·출차 사건 CSV | `event_id,video_id,slot_id,direction,frame_id,observe_start_frame,observe_end_frame`. `direction`은 `entry` 또는 `exit`이며 `frame_id`는 사람이 확인한 상태 변경 프레임이다. 관측 구간 `[observe_start_frame,observe_end_frame)`에는 전환 전 상태도 포함한다. 검증용과 최종 테스트용 사건을 따로 둔다. |
| 실행 설정 | 픽셀 비율 전처리·형태학, 라플라시안 설정, 연결성분 최소 면적, 안정화 시간, 칸별 최소 보정 표본 수, 속도 측정에 사용할 영상·해상도·표시·기록 조건. 설계값과 실제 적용값을 결과에 함께 남긴다. |

아래는 구현한 CLI 형식이다. [평가 목록 예시와 실행 안내](../../README.md#알고리즘-정량-평가)를 참고한다.

```powershell
python -m parking_monitor evaluate validate --manifest <평가목록.json> --out <검증결과폴더>
python -m parking_monitor evaluate freeze --validation-run <검증결과폴더> --out <frozen.json>
python -m parking_monitor evaluate test --manifest <평가목록.json> --frozen <frozen.json> --out <최종결과폴더>
```

- `validate`는 보정·검증 데이터만 읽는다. 각 구성의 칸별 기준을 보정하고 검증 결과와 설정을 저장한다.
- `freeze`는 검증 결과를 읽어 시연 후보를 선정한다. 비교한 구성, 입력 식별 정보, 구성별 임계값과 선택 이유를 `frozen.json`에 기록한다. 기준을 모두 충족한 구성이 없으면 검증 결과에서 선택한 후보와 이유를 입력받아 미달 항목을 함께 기록한다.
- `test`는 동결한 구성과 임계값으로 최종 구간을 실행한다. 결과에는 시연 후보를 표시한다. 미리 정한 조건과 동결 파일을 기준으로 결과를 보고한다.

## 프레임 처리와 판정

```text
저장 영상과 ROI
  ├─ 픽셀 비율     이진화 → 형태학 → 연결성분 필터 선택 → ROI별 흰 픽셀 비율
  └─ 라플라시안    평활 → 부호 있는 실수 응답 → ROI별 절댓값 평균
                           ↓
            칸별 임계값 → 단독 또는 일치 판정 → 시간 안정화 선택
                           ↓
                       최종 상태 → 공통 평가
```

1. **보정.** 보정 구간의 양 상태 정답으로 `(view_id, slot_id, 특징 설정)`별 하한·상한을 구한다. 픽셀 비율의 필터 적용판은 기준판과 별도로 보정한다. 미보정 칸은 출력 보류로 집계한다. 픽셀 비율 임계값은 [0, 1] 범위에서, 라플라시안 임계값은 원래 응답 단위의 유한한 비음수 범위에서 검증한다.
2. **검증·테스트 실행.** 각 구간은 프레임 순서대로 처리하고 ROI 마스크는 한 번 만들어 재사용한다. 필터와 특징은 프레임 영상에서 계산한 뒤 마스크 안의 값을 집계한다. 결합은 빈자리 또는 점유 후보가 두 경로에서 일치할 때 그 상태를 사용하고, 그 외는 보류로 표시한다.
3. **시간 안정화.** 입력·구간이 바뀌면 보류에서 시작한다. 후보가 바뀌거나 보류가 나오면 즉시 보류로 표시하고 시간을 초기화한다. 동일한 확정 후보가 설정 시간만큼 연속되면 확정한다. 저장 영상 시각은 `frame_id / FPS`를 사용한다. 안정화와 사건 지연에는 구간의 연속 프레임을 사용한다.

## 지표와 선택 기준

**분류.** 기존 `baseline.evaluate()`에 구성별 `(정답, 최종 출력)` 쌍을 넘긴다. 빈자리가 양성이고, 빈자리 정답에 대한 보류는 FN에 포함한다. 점유를 빈자리로 표시하면 FP다. 사람이 판단하지 못한 정답 `unknown`은 집계에서 제외하고 수를 별도로 기록한다. 분모가 0이면 지표를 `null`로 기록한다. 전체 F1은 영상별 F1의 평균 대신 합산한 2×3 혼동표에서 계산한다.

**지연.** 각 사건의 정답 전환 시각부터 전환 이후 올바른 상태를 처음 확정한 시각까지를 잰다. 관측은 제안서에 따라 정답 전환 후 10초, 다음 실제 전환 직전, 지정 관측 구간 끝 중 먼저 도달하는 시점까지 한다. 정답 전환 전에 목표 상태가 확정되면 조기 확정으로 기록한다. 관측 끝까지 올바른 확정이 없는 사건은 미검출로 센다. 입차·출차별 성공 수, 미검출 수, 지연 중앙값과 최댓값을 기록한다. 실제 상태가 일정한 구간의 잘못된 확정 전환과 보류 진입은 칸·분당 횟수로 기록한다.

**속도.** 동일 CPU, 영상, 해상도, 칸 수, 기록 조건에서 구성별로 따로 실행한다. 영상당 최대 30프레임 워밍업 후 지정된 평가 구간 전체를 측정한다. 알고리즘 시간과 디코딩·CSV 기록을 포함한 전체 루프 시간의 중앙값·95백분위, 전체 FPS를 기록한다. 프로그램의 속도 측정은 표시창 없이 진행한다. 파일 처리량, 입력 FPS, 영상 시각 기준 판정 지연을 구분한다. 제안서의 15 FPS 목표는 CPU·720p·20칸 조건에 적용한다.

**시연 후보 선택.** 검증에서 거짓 빈자리율 5% 이하 및 확정 비율 95% 이상을 충족한 구성 중 빈자리 F1이 가장 높은 것을 고른다. 동률이면 같은 측정 조건에서 전체 루프 시간이 짧은 쪽을 택한다. 정답이 부족해 지표를 계산할 수 없을 때는 검증 결과에 표본 부족을 표시한다. 최종 테스트에서 F1 0.90, 확정 비율 95%, 거짓 빈자리율 5% 목표의 달성 여부와 실제 표본 규모를 보고한다.

## 결과 파일

실행별 하위 폴더를 `results/runs/quantitative-evaluation/`에 만든다. 실행 ID가 겹치면 새 경로를 지정한다. 결과 파일을 모두 작성한 뒤 완료된 폴더로 옮겨 중단된 실행과 구분한다.

| 파일 | 기록 내용 |
| --- | --- |
| `comparison.csv` | 구성·안정화 시간, 분류 표본 수, 빈자리 F1, 거짓 빈자리율, 확정 비율, 처리 FPS, 입·출차 지연, 미검출 수 |
| `predictions.csv` | 구성 ID, 영상·프레임·칸 ID, 영상 시각, 정답, 두 특징값, 후보, 최종 상태, 분류 평가 대상 여부 |
| `events.csv` | 구성 ID, 사건 ID, 방향, 정답 시각, 최초 확정 시각, 지연, 조기 확정·미검출 여부 |
| `metrics.json` | 영상별·전체 혼동표와 지표, 보류·불명·미보정 표본 수, 측정 조건과 실패 사유 |
| `run_info.json` | 실행 단계, 입력·설정·코드 버전과 해시, 실제 영상 조건, 표본 규모 및 경고 |
| `thresholds.json` | 구성별·고정 시점별·특징별·칸별 보정 임계값 |
| `frozen.json` | 시연 후보와 선택 근거, 검증에서 사용한 비교 구성 전체의 설정·임계값, ROI·분할 식별 정보 |

## 구현 순서와 완료 조건

1. 단일 픽셀 기준선을 공통 평가기로 재현한다. 기존 `pixel_ratio.py`, `baseline.py`, `roi.py`, `video.py`, `splits.py`를 재사용한다. 같은 표본과 입력 설정에서 기존 픽셀 기준선의 혼동표와 값이 일치해야 한다.
2. 라플라시안 특징, 일치 판정, 시간 안정화를 연결한다. 원래 응답값에서의 임계값, 두 경로 불일치, 보류 후 복귀, 분할 경계의 초기화, 정답 없는 연속 프레임에서의 타이머 동작을 확인한다.
3. 동일 학교 영상에서 A·A-CC·B·C·D·D-CC 비교표를 만든다. 분류 정답 키가 구성마다 동일한지 확인하고, 방향별 사건 결과와 속도 측정 조건을 기록한다.
4. 동결 파일로 별도 테스트를 재현한다. 같은 입력과 설정에서 예측·혼동표·사건 집계가 일치해야 한다. 처리시간은 반복 측정값으로 보고한다. 목표 표본인 200프레임·입출차 10건이 부족하면 실제 확보 수를 남긴다.

현재 공통 영상의 검수 라벨 30행은 보정 구간에 있고 독립 검증 정답은 0행이다. 이 데이터로 기존 픽셀 기준선과 평가 프로그램의 동작을 점검할 수 있다. 방식 선정과 최종 성능 보고에는 학교 앞 촬영본, 검증·테스트 정답, 입·출차 사건 구간이 필요하다.
